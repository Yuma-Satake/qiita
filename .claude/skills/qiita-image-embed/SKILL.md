# Qiita画像埋め込みワークフロー

## 背景

Qiitaは画像をGUIのエディタにドラッグ&ドロップすることでしかアップロードできず、API・CLIからは画像をアップロードできない。そのためこのワークフローには必ずユーザーによる手動アップロードが挟まる。

一方でQiitaのエディタは、ドロップした画像のファイル名をそのまま使って `![ファイル名](アップロード後のURL)` という行を自動生成する。つまり、アップロード前のファイル名を画像の内容が分かる説明的な名前にリネームしておけば、アップロード後もその説明がalt文字列として記事に残る。この性質を利用して、「ファイル名を経由して画像の説明とURLを紐付ける」のがこのワークフローの核となる考え方である。

## 全体の流れ

1. ユーザーから画像が入ったディレクトリのパスと、対象の記事ファイル(`public/*.md`)を受け取る
2. 各画像をReadツールで確認し、内容が分かる説明的なファイル名にリネームする
3. 記事内の該当箇所に「アップロード待ち」を示すプレースホルダーコメントを設置する
4. ユーザーにリネーム後のファイルをQiitaのGUIエディタにドラッグ&ドロップしてもらい、生成された `![ファイル名](url)` の行をまとめて貼り付けてもらう
5. 貼り付けられた内容を`scripts/apply_image_urls.py`でパースし、プレースホルダーを実際の画像Markdownに機械的に置換する

以下、各ステップの詳細。

## ステップ1: 対象の確認

画像ディレクトリと対象記事が両方ユーザーの発言から明らかならそのまま進めてよい。どちらか曖昧な場合（複数の記事が候補にある、ディレクトリ内に記事と無関係な画像が混ざっていそう、など）は AskUserQuestion で確認する。ここを推測で進めると後続のリネームや挿入位置がすべてズレるので、曖昧なまま進めない。

## ステップ2: 画像を確認してリネーム

各画像ファイルをReadツールで開いて内容を確認する（スクリーンショット、登壇資料のスライド、人物写真など）。

リネームの方針:
- ファイル名は日本語の説明でよい（この記事群は日本語話者向けのため、英語kebab-caseより日本語の方が内容が直感的に伝わる）。ただし記事の文脈（例: 「セッションスライド」「アイコン画像」など）を踏まえて、他の画像と区別がつく具体的な名前にする
- 拡張子は変更しない
- ファイルパス・URLとして問題を起こす文字（`/ \ : * ? " < > |` や制御文字）は避ける
- 同じディレクトリ内で名前が衝突しないように注意する（`mv`する前に対象ファイル名が既に存在しないか確認する）
- リネームは`mv`コマンドで行う。ユーザーの手元のファイルを直接書き換える操作なので、対象ディレクトリとファイル数を一度ユーザーに見せてから進めるとよい

## ステップ3: プレースホルダーの設置

記事のMarkdownを読み、画像を挿入すべき位置を決める。

- 記事内に既に `<!-- 画像を入れる -->` や `<!-- 画像: セッションスライド -->` のような画像プレースホルダーコメントがある場合は、それを手がかりに「どの画像がどのプレースホルダーに対応するか」を文脈（見出し・直前の話題）から判断する
- プレースホルダーが無い場合は、記事の見出しや文章の流れから、その画像がどの話題に対応するかを判断して適切な位置に新しく挿入する。判断に自信が持てない場合は無理に決め打ちせず、ユーザーに挿入位置の候補を示して確認する
- 対応が決まったら、その位置のコメントを次の形式に統一する（新規挿入の場合もこの形式でコメントを書く）:

  ```
  <!-- 画像アップロード待ち: リネーム後のファイル名.拡張子 -->
  ```

  この文字列は後続ステップでスクリプトが機械的にマッチングするための目印なので、ファイル名は実際にリネームした名前と完全に一致させること（表記ゆれがあるとステップ5で拾えない）

- 全ての画像についてプレースホルダーを設置し終えたら、リネーム後のファイル一覧と、それぞれがどのプレースホルダーに対応しているかをユーザーに提示する

## ステップ4: ユーザーによるアップロードを待つ

ユーザーに次を依頼する:
- リネーム済みの画像ファイルをQiitaの編集画面にドラッグ&ドロップでアップロードする
- アップロードすると自動的に `![ファイル名](https://qiita-image-store...)` という行がエディタに挿入されるので、それを全部まとめてコピーしてこちらに貼り付けてもらう

ユーザーが画像を1枚ずつアップロードするか、まとめてアップロードするかは自由。貼り付けてもらう内容は複数行の `![ファイル名](url)` の羅列で構わない（順不同でよい、ファイル名で紐付けるため）。

## ステップ5: URLの反映

ユーザーから貼り付けられた `![ファイル名](url)` の羅列を一時ファイルに保存し、`scripts/apply_image_urls.py` を実行してプレースホルダーを実際の画像Markdownに置換する。

```zsh
python3 .claude/skills/qiita-image-embed/scripts/apply_image_urls.py <記事ファイルパス> <URL一覧を保存した一時ファイル>
```

このスクリプトは:
- `![ファイル名](url)` を全行パースする
- 記事内の `<!-- 画像アップロード待ち: ファイル名 -->` を探し、ファイル名（完全一致、無ければ拡張子を除いた名前で一致）が合うものを `![ファイル名(拡張子なし)](url)` に置換する
- 置換できたもの・対応するプレースホルダーが見つからなかったURL・URLが来なかった未使用のプレースホルダーを、それぞれ標準出力に一覧表示する

実行後、出力される警告（未対応のURL・未使用のプレースホルダー）を確認し、ある場合はユーザーに報告して手動での対応を相談する。全て解決したら、置換後の記事をユーザーに見せて完了を報告する。

一時ファイルは`/tmp`や作業用スクラッチディレクトリに置き、作業が終わったら削除してよい。
